Console popup watch

Catch the 1‑second black / console windows that Windows tooling flashes at you, fix the spawns that cause them, and prove the fix did not silently revert. A small, dependency‑free toolkit plus the method behind it.

What this is. Two stdlib‑only Python scripts — a watcher that records every new visible top‑level window with the parent chain that created it, and a three‑place byte‑match that proves a fix is still in place in every copy. Both were built and used on a real Windows box to verify a tooling‑wide console‑flash repair (10 flashes in 23 minutes → 0 in a 15‑minute window, with the watcher proven not blind).

The symptom

You run an editor, a terminal‑based agent, a GUI app, or a scheduled job — and every few seconds or minutes a one‑second console window flashes, or a black window appears and vanishes faster than you can read it. Often it titles itself with an interpreter path (C:\…\python.exe) or cmd.exe. On busy days it looks like a “waterfall” of black rectangles over your desktop.

The flashes are child processes you did not launch by hand — hooks, guards, MCP servers, probes, watchers — that your tooling spawns on every event.

Why it happens

On Windows a .exe is either a console subsystem image (python.exe, cmd.exe, node.exe is console too) or a GUI subsystem image (pythonw.exe, most editors). A console child always gets a console:

  • If the parent already has a console, the child inherits it — nothing appears on screen.
  • If the parent has no console (GUI app, pythonw, service, TUI host), Windows allocates a new one — and that is the visible flash.

The fix is always one of two moves: tell the child not to allocate a visible console (CREATE_NO_WINDOW / windowsHide), or let a console‑less parent hand it one invisibly (hidden launcher, pythonw, STARTUPINFO with SW_HIDE).

The classic trap. Your tooling spawns python.exe from a GUI parent just to probe something (check an interpreter, run a hook). That probe allocates a console window for ~1 s on every single event — the most common single source of “what is this black flash?”. Probe with pythonw.exe, or pass CREATE_NO_WINDOW, or check once and cache the answer.

Fix patterns

Node / TypeScript — child_process

const { spawn, spawnSync, execFile, exec } = require("child_process");

// Every call site, every time — a different call without the flag still flashes:
spawn(cmd, args, { windowsHide: true });
spawnSync(cmd, args, { windowsHide: true, encoding: "utf8" });
execFile(cmd, args, { windowsHide: true });
exec(cmd, { windowsHide: true });            // prefer execFile where possible

// Gotchas
// • The flag is per-call. A wrapper that hides does NOT cover direct calls next to it.
// • `detached: true` does not hide anything by itself.
// • Audit with a repo-wide scan (the fix is only as good as its weakest call site):
//   grep -rEn "spawn(Sync)?\(|execFile\(|exec\(" --include=*.ts --include=*.js .

Python — subprocess

import subprocess, sys

NO_WINDOW = getattr(subprocess, "CREATE_NO_WINDOW", 0)  # Windows-only constant

subprocess.run([sys.executable, "tool.py"], creationflags=NO_WINDOW, check=False)
subprocess.Popen(["cmd.exe", "/c", "ping -n 2 127.0.0.1"], creationflags=NO_WINDOW)

# Shell-route alternative (STARTUPINFO):
si = subprocess.STARTUPINFO()
si.dwFlags |= subprocess.STARTF_USESHOWWINDOW
si.wShowWindow = 0  # SW_HIDE
subprocess.run(["cmd.exe", "/c", "whoami"], startupinfo=si, creationflags=NO_WINDOW)

# Interpreter probes from hooks/guards: use pythonw.exe, not python.exe.
#   \pythonw.exe your_script.py

PowerShell / scheduled tasks / .cmd wrappers

# Start-Process hides the new console of a console child:
Start-Process -FilePath "C:\tools\probe.exe" -WindowStyle Hidden -Wait

# For .cmd/.bat wrappers, launch through a VBS shim (wscript.exe is GUI-subsystem):
#   CreateObject("WScript.Shell").Run "cmd /c ""C:\path\job.cmd""", 0, False
#   (0 = hidden window, False = don't wait)

# Task Scheduler: "Run whether user is logged on or not" executes in session 0 —
# a console there has no desktop to flash on. Otherwise the job can flash at its tick.

Verify the fix — the 15‑minute protocol

“I fixed it and the flashes stopped” is not evidence: you may have killed the feature, or the fixed code may not be loading at all (dead code cannot flash). Prove three things, in this order.

0. Baseline and heartbeat

pythonw console_watch_cal.py --duration 900 --out watch.jsonl

The watcher enumerates visible top‑level windows every 80 ms, baselines what already exists, and appends only new windows — each with window class, title, pid, PEB command line, and the parent chain up to the launcher. It writes a heartbeat every 30 s so a dead watcher is visible in the log instead of silently proving “all clear”.

1. Prove the watcher is not blind (A/B canary)

pythonw console_watch_cal.py --negctl --out negctl.jsonl

The canary spawns a control console window (cmd.exe … ping), waits for it, and then the same call with CREATE_NO_WINDOW. Expected verdict: default_spawn_windows > 0 and create_no_window_windows == 0 — "watcher_not_blind": true.

False‑negative trap. If you launch the canary from a console‑attached shell (a normal terminal‑hosted python.exe), the control cmd child inherits that console — no new window appears and both probes read 0/0. Run the canary under pythonw.exe, or force a brand‑new console for the control with cmd /c start "" cmd /c "ping -n 4 127.0.0.1 >nul" from the same shell — the new window must be caught. A 0/0 canary is inconclusive, never “clean”.

2. The interception window

Run the watcher for ≥15 minutes while the estate is genuinely active (your normal work — hooks firing, agents reading files, builds running). Verdicts:

  • 0 new visible windows with heartbeats throughout → the spawn surface is quiet. Cross‑check with step 0’s baseline and the canary from step 1.
  • Any window → name it from the JSONL: cmdline (PEB), parent chain, class, elapsed. Fix that spawn or file it; do not average it away.

3. Prove the fix did not revert

# live copy vs second deploy copy vs the canonical repo HEAD — CRLF-normalized
python byte_match_3way.py --live C:/Users/you/.config/app/live \
    --deploy C:/Users/you/deploy/app --repo C:/src/app \
    --file hooks/guard.ts --file hooks/probe.ts

Exit 0 means every copy carries the same bytes (after CRLF→LF normalization — a CRLF difference is an EOL artifact, not a revert). Exit 1 names every drifted file. Run it before and after the interception window: a mid‑run revert (a sync job copying a stale “losing copy” over your fix) shows up as a byte change.

Traps worth knowing

TrapWhat to do
Dead code cannot flash — “quiet” may mean the fixed plugin never loads.Check that the component actually loads at boot (logs often show module‑load errors). A boot‑rejected plugin looks exactly like a perfectly fixed one.
A sync/backup job copies an unfixed copy over the fix.Register the fixed call sites in a guard the sync honors in both directions, or make the sync refuse copies with fewer hidden‑call sites. Then run the byte‑match before/after.
Third‑party updaters overwrite your live patch.Fix it upstream in the owning repo; keep a local patch only as a stopgap and re‑verify after every update.
Broker / higher‑integrity processes give an empty PEB command line.The parent chain still resolves — attribute via ancestry, not cmdline, for those windows.
Scheduled tasks tick outside your window.Check the schedule (next‑run time) before declaring the system quiet; a task at 06:30 cannot be caught by a 15‑minute evening run.
The control flash and the suppressed spawn disagree with a real estate spawn.That is the point: the canary must reproduce both outcomes (visible window / none) under your exact session and window station.

Download

console_watch_cal.py — window watcher + A/B canary (239 lines, stdlib + ctypes only) byte_match_3way.py — three-place, CRLF‑normalized byte‑match (exit 0 / 1)

Both scripts are dependency‑free, read‑only, and write only the JSONL you name. Python 3.8+ on Windows; the watcher uses ctypes and touches the Win32 API (EnumWindows, Toolhelp32, NtQueryInformationProcess).

Method notes

  • Measure in your window station: the watcher must run in the same desktop context as the tooling you are judging.
  • 15 minutes minimum, with the estate active; 30‑s heartbeats make silence auditable.
  • Keep the raw JSONL: it is the receipt (timestamp, pid, class, cmdline, ancestry) that lets anyone re‑check your claim.
  • Verify after the fix with the same instruments you used before it — otherwise you are comparing a measurement to a memory.
