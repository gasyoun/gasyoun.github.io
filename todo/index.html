Phase 0 — Mac prep [MAC]

  1. Open Terminal (Cmd+Space → “Terminal” → Enter). Verify Homebrew actually finished: 
    brew --version

    If “command not found”: quit Terminal fully (Cmd+Q), reopen, retry once. Still missing → rerun the Homebrew installer script and let it finish completely (it asks for your Mac password midway).

  2. Install base tools (pwsh keeps your setup byte-compatible — your opencode config says shell: pwsh): 
    brew install git gh node python@3.12 ripgrep jq powershell
  3. Create target directories for incoming files: 
    mkdir -p ~/.config/opencode ~/.grok ~/.local/share/opencode ~/.agents ~/.ssh ~/.secrets ~/Documents/GitHub
  4. Note your identity for the network transfer: 
    whoami                          # macOS username
scutil --get LocalHostName      # Mac hostname

    Put both into the “Machine parameters” card above.

  5. Enable the SSH server: System Settings → General → Sharing → turn ON “Remote Login” (allow your user). This is the Mac’s one-toggle equivalent of installing OpenSSH Server on Windows.

Phase 1 — File push over LAN [WINDOWS]

Run from Windows PowerShell. First contact asks to trust the host fingerprint → answer yes, then enter your Mac login password when asked.

  1. Test connectivity: 
    ssh <macuser>@<machost>.local "echo ok"
  2. Push the non-git skill trees (Grok CLI also reads ~/.agents/skills): 
    scp -r C:\Users\user\.agents <macuser>@<machost>.local:.agents
  3. Push SSH keys + known_hosts (keeps prod hosts trusted): 
    scp -r C:\Users\user\.ssh <macuser>@<machost>.local:.ssh
  4. Push secrets (LAN only — never through any repo, cloud drive, or email): 
    scp -r C:\Users\user\.secrets <macuser>@<machost>.local:.secrets
  5. Push OpenCode global config files (node_modules deliberately excluded): 
    scp C:\Users\user\.config\opencode\AGENTS.md C:\Users\user\.config\opencode\package.json C:\Users\user\.config\opencode\package-lock.json C:\Users\user\.config\opencode\opencode.jsonc <macuser>@<machost>.local:.config/opencode/
scp -r C:\Users\user\.config\opencode\command C:\Users\user\.config\opencode\tools <macuser>@<machost>.local:.config/opencode/
  6. Push Grok portable parts: 
    scp -r C:\Users\user\.grok\skills C:\Users\user\.grok\rules C:\Users\user\.grok\agents C:\Users\user\.grok\workflows <macuser>@<machost>.local:.grok/
scp C:\Users\user\.grok\auth.json C:\Users\user\.grok\config.toml <macuser>@<machost>.local:.grok/
  7. Push OpenCode model logins (so no re-login is needed): 
    scp C:\Users\user\.local\share\opencode\auth.json C:\Users\user\.local\share\opencode\account.json <macuser>@<machost>.local:.local/share/opencode/

    If OpenCode still asks for a model login afterwards, run /login inside it.

Phase 2 — Assemble on Mac [MAC]

  1. Fix SSH key permissions — macOS refuses world-readable private keys: 
    chmod 700 ~/.ssh
chmod 600 ~/.ssh/id_ed25519 ~/.ssh/ors-faq-deploy
chmod 644 ~/.ssh/*.pub ~/.ssh/known_hosts
  2. Rewrite the six hardcoded Windows paths in the OpenCode config (C:/Users/user → your home): 
    sed -i '' "s|C:/Users/user|$HOME|g" ~/.config/opencode/opencode.jsonc
cat ~/.config/opencode/opencode.jsonc   # eyeball: no C:/ left, shell stays pwsh
  3. Rebuild the OpenCode plugin dependencies: 
    cd ~/.config/opencode && npm install
  4. Install OpenCode natively: 
    curl -fsSL https://opencode.ai/install | bash
  5. Install Grok CLI natively (superagent-ai/grok-cli — same product as on Windows, v1.0.5 there): 
    curl -fsSL https://raw.githubusercontent.com/superagent-ai/grok-cli/main/install.sh | bash
  6. Authenticate GitHub (browser device flow) and wire git credentials: 
    gh auth login        # pick: GitHub.com → HTTPS → "Login with a web browser"
gh auth setup-git
  7. Set git identity — copy the exact values from Windows first (git config --global user.name / user.email), then: 
    git config --global user.name "<same as Windows>"
git config --global user.email "<same as Windows>"
  8. Clone the two private config repos straight into place: 
    gh repo clone gasyoun/claude-config ~/.claude   # 86 skills + rules
gh repo clone gasyoun/codex-config ~/.codex
  9. Clone the working repos (Uprava hub first) and enable its commit guard: 
    gh repo clone gasyoun/Uprava ~/Documents/GitHub/Uprava
cd ~/Documents/GitHub/Uprava && git config core.hooksPath .githooks

    Clone further repos as needed into ~/Documents/GitHub/; set core.hooksPath .githooks wherever the guard applies.

Phase 3 — Verify [MAC]

  1. Toolchain versions all print cleanly: 
    opencode --version && grok --version && pwsh -v
  2. Skill counts match this machine: 
    ls ~/.claude/skills | wc -l    # expect ~86
ls ~/.agents/skills | wc -l    # expect ~34
  3. GitHub auth resolves to gasyoun over HTTPS: 
    gh auth status
  4. Smoke test in the real workspace — skill list should mirror Windows (~120 across the four dirs), then run one command: 
    cd ~/Documents/GitHub/Uprava && opencode    # check skills load, run next-task
Security rules (non-negotiable)
  • .secrets, SSH keys, and every auth.json travel by LAN scp only — never through any git repo, cloud drive, messenger, or backup sync.
  • Never sync or publish ~/.worktree-attic (holds real payloads incl. .env files).
  • SSH keys must be chmod 600 on macOS or ssh refuses them silently-looking.
  • All Uprava safety rules carry over automatically — they are repo/git-level, not OS-level: worktree-first off origin/main, never commit in the shared main tree, git fetch before handoffs, attic never synced.
  • Optional cleanup after migration: turn “Remote Login” back off in System Settings.
