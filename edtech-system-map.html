1. Identity

  • Public name: «Институт исследования санскрита» (Institute for Sanskrit Research). Founder-led online institute teaching Sanskrit and Hindi to Russian-speaking learners: grammar from zero to classical-text reading, chanted texts (Bhagavad Gītā, Yoga Sūtras), Vedic literature, indology subjects (astronomy, calendars, geography of India).
  • Model: live cohort groups (weekly Zoom lessons, ~8-lesson blocks) + recorded self-serve courses. Public prices: ~RUB 4,800–8,000 per block.
  • Scale (public aggregates, 09-09-2026): 50+ visible course pages, ~90 groups total including recorded streams, hundreds of registered learners, active group sizes 1–42. Support corpus: ~3,000 real support dialogs (2022–2026).
  • Team: solo founder-linguist + curator + accountant + external teachers. RU market, Telegram-centric acquisition, 152-FZ constraints.

4. Learning engine (all DONE and live unless stated)

  • Course structure: Course → Block → Lesson; group-based access granted automatically on payment; full-course, per-block, half-block tariffs.
  • SRS (spaced repetition): native FSRS-scheduled trainer ("Anki for Sanskrit") — decks, daily new-card limits, per-user private decks, answer-history intervals, stats. ON. Game events seed initial decks.
  • Dictionary: multi-dictionary lexical base, Devanāgarī / IAST / Cyrillic / translation per word, FULLTEXT search.
  • Drills ("lila" engines): browser trainers — sort / match / cloze / table — plus ligature and root-frequency decks; soft gate (one game free → register).
  • Reading packs: cohort-based graded reading ("Start Reading") from the research corpus spine; entitlements tied to course cohorts.
  • Homework: loop draft → submitted → needs_revision → accepted with curator review, files, comments, Telegram/VK push verdicts, bulk review queue. Human-in-the-loop by design — see §9.
  • Live lessons: schedule + calendar; Zoom auto-creates ONE recurring meeting per course; attendance webhooks; recordings ingested and gated by entitlement.
  • Progress: lesson-view heartbeat, append-only activity events, onboarding checklist, "next lesson" hints, stuck-student reports, goal check-ins, discipline score.
  • Gamification: two-counter loyalty currency "prana" (discount wallet + lifetime rank Śiṣya→Paṇḍita), leaderboard, badges, streaks, seasonal competitions, prana shop, P2P transfer.
  • Certificates: PDF with public verification route + milestone auto-issuance.

6. Personalization — what exists today

  1. Per-learner FSRS scheduling (per card, per user), per-deck daily limits — live.
  2. Game-event-seeded initial SRS decks — live.
  3. Per-learner pricing: loyalty tiers, personal discounts, deposits, upgrade credit — live.
  4. Marathon funnel: per-enrollment day-by-day content, warm-tail waves, A/B arm field — live.
  5. Placement: marathon level-quiz + external exam-score import — partial (no full adaptive placement engine).
  6. Adaptive grammar recommender + mastery projection — built, OFF.
  7. Goal check-ins, discipline score, stuck-student signals, onboarding checklist — live.
  8. Curated per-track practice (e.g., Hindi Telegram practice) — live.

7. AI & agents — what exists today

  1. Support AI: RAG over the FAQ knowledge base (BM25 + hybrid retrieval; embeddings incl. local Ollama) + LLM draft/auto-reply on Telegram/VK/web with a shadow→live promotion ladder. The ~3,000 real support dialogs are the moat.
  2. Message-intent classifier: hybrid regex+LLM router for support, vendored ML tool, fed by PII-masked dialog corpora.
  3. Bounded student agent: in-cabinet assistant, exactly 3 tools, confirm gate (flag OFF).
  4. Lecture AI: slide structure/correction/placement for lecture authors.
  5. Content pipeline: n8n lecture-clip → multi-format content candidates with human acceptance.
  6. Cost/ops: OpenRouter balance tracking; local Ollama experiments; support-history analytics with human-vs-AI reply breakdown.
  7. By design, NOT built: automated homework grading (curator loop is the product), free-form AI tutor, student-facing AI content without human acceptance.

8. Automation & operations

  • n8n layer (separate host): ~76 documented workflows — lecture-clip extraction (ffmpeg), Zoom recording delivery, schedule-sheet sync, VK calendar posting, exam-score sync, alerting→GitHub issues.
  • In-app cron: 92 scheduled commands/jobs (marathon delivery, warm tails, support sync, club expiry, season open, shortfall notifications…).
  • Webhooks: payment provider, Telegram, VK, lead-magnet bots — signature-verified.
  • Email: ~40 mailables + in-house campaign/newsletter engine (suppression list, near-duplicate detector, inbound email).
  • Ops: script-only deploys, spatie backups, Better Stack uptime monitoring, restore drills performed, server resource guards.

9. Deliberate non-goals (do not recommend these)

  1. No automated homework grading — curator feedback IS the pedagogy.
  2. No free-form student AI tutor — bounded 3-tool agent instead; trust before capability.
  3. No multi-tenancy/white-label — one institute, deliberately.
  4. No league-table gamification beyond seasons/prana — adult academic audience.
  5. RU-first UI; no interface i18n yet.
  6. No third-party public API yet.

11. The research spine behind the platform (the moat)

The shop sits on a large public research estate: Cologne-family Sanskrit dictionaries digitized and corrected (CDSL program), machine-translation of a monumental Sanskrit dictionary (PWG→RU), grammar-textbook claim-verification corpora, Rig-Veda and other text layers, a spoken-Sanskrit corpus, Russian style-council tooling for editorial quality, and a customer-development corpus of ~3,000 support dialogs. Datasets are registered and openly licensed where rights allow (CC BY-SA). Rare among edtech players: platform content is derived from openly published, versioned research data, not a closed authoring tool.
