# MG ruling 25-11-2026: внутреннее и внешнее не смешивать

MG, 25-11-2026, verbatim: «внутренние и внешние незачем смешивать. Зачем читателям знать, что нужно делать админу?»

Один документ не может обслуживать две аудитории. Внешняя страница — только то, что нужно читателю/покупателю: что и как купить, цены, условия, контакты. Внутренний документ — админские и операционные детали: флаги, Filament-ресурсы, остатки и резервы, статусы заказов, прод-хосты, бэкапы, риски, GTD-остатки.

Практика: сначала разделить аудитории, потом писать. Если материал уже смешан — делать внешний HTML заново из внешней части, а не «вычищать» internal-документ для публикации. Связка между ними — одна ссылка с внутреннего документа на публичную страницу.

Конкретный повод: `BOOK_CLUB_FINAL_GUIDE.md` в `book-club-219924` был написан с обеими частями сразу; по рулингуMG внешняя часть вынесена на `gasyoun.github.io/book-club/`, внутренняя оставлена в `book-club-219924`.

См. также [2026-11-25-public-export-html-not-markdown.md](2026-11-25-public-export-html-not-markdown.md).
